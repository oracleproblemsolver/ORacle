구성
디자인 패턴 파악: 웹 프론트의 시간 이산화 값을 격자점으로 시각화해서 디자인 패턴을 파악한다.
점화식 이산화: 파악한 패턴을 점화식으로 이산화한다.
과거값 → 쿠키 → WAS: 점화식의 과거 순서에 해당하는 쿠키를 WAS에 넘겨준다.
프록시 진입: 그렇게 동작한 백엔드 도메인의 프록시로 진입한다.
현재값 → 세션 ID 생성: request 값에 격자점 점화식의 현재값에 맞는 순서대로 세션을 대입하면 세션 ID가 생성된다.
미래값 → 복호화 → response: 미래값에 해당하는 격자점 점화식을 도메인에 주입하면 AES 암호가 풀리면서 response(API)가 나온다. 즉 API의 https/http, LocalC:Local:D.
노드 접근: 그 뒤 node를 보기 위해서는 tcp/udp request 라우팅 프로토콜을 거친다.
전역상수와 매개변수는 일방향 벡터이기 때문에 p=np는 성립하지 않는다
DB 점검: query에 조건문이 있는지 확인한다.
RSA 스위칭 포인트 체크: 볼 수 없으면 RSA 스위칭 포인트를 체크한다.
한 줄 흐름
프론트 시간이산화 값 → 격자점 시각화 → 디자인 패턴 → 점화식 이산화 → (과거값=쿠키→WAS) → 백엔드 도메인 프록시 진입 → (현재값 순서로 세션 대입 → 세션 ID 생성) → (미래값 점화식 주입 → AES 복호 → response API: https/http, LocalC:Local:D) → node 접근: tcp/udp 라우팅 → DB 점검: query 조건문 확인 → 안 보이면 RSA 스위칭 포인트 체크
